This is the complete disposition of all 283 tables in
`EXPECTED_AUTHORITY_TABLES`. It is a design result, not a migration plan and
not permission to drop a database. Historical rows are not migrated.

## Audit method and limits

- Table identity and introducing migration were parsed from the current schema
  catalog and 106 SQL migrations.
- Writers are modules containing literal `INSERT INTO`, `UPDATE`, or
  `DELETE FROM` for the table. Readers contain literal `FROM` or `JOIN`.
- Dynamic SQL, trigger-only writes, table-name indirection, and imports are
  labelled from static references rather than falsely reported as exact SQL.
- “Current owner” is derived from literal writer modules; multiple bounded
  owners are marked **AMBIGUOUS**. With no literal writer it is explicitly
  inferred from references/table family.
- Static absence is not runtime non-use proof; the implementation phase must
  repeat call-chain and query-log inspection before deletion.
- Current business row counts were not available to the audit role. Data
  migration is out of scope, but any destructive operator action still requires
  the schema-epoch/catalog preflight in ADR-015.

## Disposition semantics

- **KEEP**: target retains the responsibility without a competing owner. DDL is
  still rebuilt in the new epoch.
- **MERGE**: business meaning/lineage survives under the listed target owner(s);
  old table identity and writer path do not.
- **DERIVE**: stable information is computed from canonical facts; persisting it
  would recreate a truth source.
- **DELETE**: the table protects only compatibility, pseudo-security, or
  implementation guard mechanics with no retained business fact.

## Implementation deletion gate

A current table can be removed only when its target owner/constraint/query tests
pass, every literal and dynamic writer/reader is removed or redirected, no
installed CLI/composition root reaches it, and the clean epoch baseline contains
neither the table nor a compatibility view. There is no dual-write or legacy
read period after Hard Cutover.
