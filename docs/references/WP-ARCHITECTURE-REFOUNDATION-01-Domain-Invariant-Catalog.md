## Deletion gate

A legacy/current test may be deleted only when the implementation commit records:

1. every business assertion it contains mapped to one or more invariant IDs, or
   an explicit reviewed “compatibility bytes only; no data migration” decision;
2. target unit/integration test path and exact passing command;
3. target owner/table/constraint where applicable;
4. proof that no canonical entry point imports the old code;
5. no weakened assertion, broader tolerance, skip, xfail, or compatibility hook;
6. review of empty, unknown, negative, conflict, restart, and concurrency cases;
7. deletion in the same dependency-coherent checkpoint as the last consumer.

A target test must assert business semantics, not merely that the new class/table
exists. Differential harnesses are temporary implementation aids and cannot
remain as permanent dual semantics.
